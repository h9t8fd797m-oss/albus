# Plan — 2026-08-25

## Decision: chat optimisation is deferred to last

Ask Albus answers well on curriculum questions but is expensive, and Felipe
reports it is not working well generally. **Both stay parked until everything
else is done.** What follows is the diagnosis so the work is cheap to pick up,
not an invitation to start it now.

### Measured cost, from `ai_usage`

| kind | model | avg input | avg output |
| --- | --- | --- | --- |
| chat (with corpus) | claude-sonnet-5 | 3,995 | 604 |
| chat (no corpus) | claude-haiku-4-5 | 338 | 79 |
| breakdown | claude-haiku-4-5 | 559 | 356 |

A curriculum-grounded turn is roughly **12x the input** of an ungrounded one and
runs on the more expensive model. Call it ~2c a message against ~0.05c.

### The specific cause, which is a defect and not a tuning knob

`chat/index.ts:234` routes to Sonnet when `knowledge.length > 0`. For an IB
student that is **always true**, because the two always-included rule sections
come back on every query regardless of the question. So "hi" costs the same as
"does an E in TOK fail my diploma" — the cheap model is unreachable for anyone
with a curriculum.

Three things to fix together, when the time comes:

1. **Route on matched sections, not total sections.** The always-included rules
   must not count as evidence that a question is about the curriculum. Have
   `loadKnowledge` report matched separately, and only escalate on those.
2. **Charge the always-included rules only when the corpus is used.** ~700 tokens
   on every message otherwise.
3. **Consider dropping the retrieval limit from 4 to 2–3.** The live tests showed
   the top two sections carried the answer in every case; the third and fourth
   were usually adjacent context.

"Not working well" beyond cost is **undiagnosed** — no examples captured yet.
Get concrete failures before changing prompts, or the fix is guesswork.

## Order of work from here

### 1. Deadline notifications — the last hole in the core loop

`NotificationScheduler` is 65 lines and only fires when a focus session ends.
**Nothing reminds a student that work is due.** A study planner that never speaks
first is a to-do list you have to remember to open.

Wanted: a local notification per assignment deadline, rescheduled whenever the
plan re-flows, cancelled on completion. Entirely on-device — no backend, no
tokens, no cost. Permission is already requested in Focus Mode, so the prompt
exists.

### 2. Run it on real hardware

Everything so far has been simulator-only. Fonts, safe areas, haptics, the
notification prompt and background/foreground transitions in Focus Mode have
never been seen on a phone.
