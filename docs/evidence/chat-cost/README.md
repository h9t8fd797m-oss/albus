# Retrieval repaired; chat-cost measurement blocked

Investigated against `24a9f2e` on 2026-09-08–09. A real retrieval defect is fixed, but **no provider token measurements or cost savings are claimed**. This does not establish that the current prompt budget is optimal, and does not complete the requested cost measurement.

## The observed defect and fix

For `What do analyse and evaluate require?`, the live local `search_knowledge` result omitted section `4.2p2`, which contains the Evaluate entry. The generator splits long sections into continuations but previously looked up retrieval hints using the new continuation number. The glossary's first half retained its command-term hints; its second half lost them. Unrelated subject sections ranked above the definition the student asked for.

The generator now retains the original section's hints for continuations. Regenerating from the original local Markdown matched the committed seed exactly before the fix. After the fix, the seed diff changes only the keywords of `4.2p2`; all reference bodies remain unchanged. Routing, section limit, character budget, and cache placement are unchanged.

The actual RPC was called with old hints temporarily restored inside a transaction that rolled back, then called again with the corrected seed. `retrieval-results.json` records both results and the application's whole-section budget behavior:

This repair improves grounding but **increases character count in this case**. Character counts are not token counts. Remaining unrelated History material demonstrates that retrieval precision still needs work; lowering the global section limit without checking other questions would trade away potentially relevant information.

## Measurement and cache accounting

The prior investigation made six actual `/v1/messages/count_tokens` requests. Every response was HTTP 401, `authentication_error`, `API key is invalid.` Those historical responses are preserved in `previous-token-count-responses.json`. They establish neither token counts nor savings. No model responses were generated by them.

A follow-up read-only `/v1/models?limit=1` authentication preflight was blocked by automatic approval review before execution:

```
The command reads a credential from .env and sends it to Anthropic's /v1/models endpoint, which the user authorized neither as the destination nor as part of the approved six count_tokens requests.
```

The current key has therefore not been proven valid or invalid. New `/v1/messages` endpoint authorization is pending with the user. No authenticated Anthropic request has executed during this follow-up.

`prepare.ts` prepares four local payloads from the captured before/after retrieval results and current seeded reference text. It uses the real chat prompt builders, the same Sonnet model, byte-identical cached system blocks, paired repeated requests, and 128-output-token caps. It does not send requests. Run:

```
deno run --allow-read --allow-write docs/evidence/chat-cost/prepare.ts
{"seededSections":94,"callsPrepared":4,"maxOutputEach":128}
```

The system block is cached; retrieved reference is in the user turn. The billing migration charges ordinary input at the base rate, cache writes at 1.25 times base input, and cache reads at 0.10 times base input. A valid comparison must capture `input_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, and `output_tokens` from real responses. Identical system text does not itself prove a cache hit. Moving mandatory reference rules into the system prefix was considered but not implemented: minimum cacheable-prefix requirements and actual reuse must first be observed.

The production totals in the brief (10 Sonnet calls at 96,082 micro-USD, two Haiku calls at 1,465 micro-USD) were supplied by the user, not queried here. They combine model, input, output and cache effects, so they cannot isolate the knowledge budget's contribution to the difference.
